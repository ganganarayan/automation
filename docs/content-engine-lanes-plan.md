# content-engine: lanes and stages restructure plan

Drafted 30-10-2026. This is a plan only; nothing in it is built yet.

## The problem

Three menu items overlap: Instances, Manual run and Ready video + AI copy. Each one creates
or edits instances, and each mixes "where the content comes from" with "what step it is
at". There is also no checkpoint between transcription and the paid AI steps. A misheard
word (STHIRA → STERA) therefore flows into every caption and every thumbnail.

## Target model

**The funnel decides the lane.** Each funnel holds:
- its name
- its **source**: a Google Sheet, a Drive folder of ready videos, or generated by the app
- its **destination** channels (Post for Me accounts)
- its schedule slots, brand brief and comment keyword
- its **clean preset** (zoom %, cut last N s), which can be locked once you're happy with it

Every item becomes one instance, whatever its lane, and moves through the same stages:

| Stage | Applies to | Gate | Costs money |
|---|---|---|---|
| 1. Prepare: ✂ Clean (bulk) | ready video | preset locked | ~1¢/video (Railway) |
| 2. Transcript | ready video | **you verify / edit / paste SRT** | Whisper only |
| 3. AI copy + thumbnails | all lanes | runs only after the transcript is approved | LLM + image |
| 4. Review & schedule | all lanes | you approve | none |
| 5. Posted log | all lanes | read-only | none |

Sheet lane: the row text plays the role of the transcript in stage 2, then continues from stage 3.
Generated lane (script → images → animate → voice → stitch): the current pipeline. It
becomes this lane's own steps, shown inside the instance. It is no longer a separate
"Manual run" menu.

## Menu after the change

- **Queue**: everything waiting for you, across funnels, sorted by stage. Examples: "3
  transcripts to verify", "2 posts to approve". This is the phone home screen.
- **Prepare**: per funnel, the source list (Drive videos / sheet rows), bulk select, ✂ Clean
  all with the locked preset, and bulk "Transcribe".
- **Calendar**: scheduled posts by day. Reschedule or cancel from the phone.
- **Log**: posted instances with real cost (today's Instances, read-only).
- **Comments**: unchanged.
- **Setup**: Funnels, API Keys (incl. system prompts), Workspace, Users.

Manual run and Ready video + AI copy disappear as menu items. Their pages become the
instance view's stage panels.

## Transcript gate (the money saver)

- Transcribe produces the transcript and stops. Status: *transcript review*.
- The transcript editor accepts a pasted SRT: timestamps are stripped before the LLM sees it,
  but kept for future subtitles.
- A **glossary** goes under API Keys (STHIRA, PrATS, Apply Gita Wisdom, …). It is passed to
  Whisper as the prompt, so the names come out spelled right the first time.
- "Approve transcript" unlocks "Generate copy + thumbnails". Regenerating either step never
  re-runs the other.

## Phone-first

- One responsive layout: cards instead of tables under 700 px, big buttons, the sidebar
  becomes a bottom bar.
- Installable as a PWA (add to home screen); the login cookie stays valid for 30 days.
- An email when something needs you ("transcript ready", "clean done", "post failed"), with a deep link
  to that item.
- Everything in the Queue and the Calendar works one-handed on a phone. ✂ Clean and
  generation run on the server, so the phone can be locked while they run.

## Video creation tools (researched 30-10-2026)

- **NotebookLM Video Overviews:** official docs describe the Studio panel only, and
  generation can take 30+ minutes. The NotebookLM Enterprise API documents notebook
  create/list/share/delete; I found **no documented video-generation endpoint**. Unofficial
  automation projects exist, but they can break or violate the terms. Cost is whatever your
  Google plan costs; there is no per-video API price.
- **Google Vids:** found no developer API; it is a Workspace app with in-app AI only.
- **Veo (Gemini API):** has an API priced per second of video. Third-party trackers
  (September 2026) list Veo 3.1 at $0.05–$0.40/s at 720p/1080p depending on tier, which
  is about $3–24 per minute. Google's pricing page didn't show Veo rates when I checked, so
  verify before budgeting.
- **Recommendation:** keep NotebookLM and Vids as the manual creative step (create, then
  drop the file in the funnel's Drive folder). Automate everything after it: clean,
  transcript gate, copy, thumbnails, schedule. That gives the best quality per rupee today.

## Phases

1. **Lanes + transcript gate:** funnel source/lane field, instance stage model, transcript
   approve step, glossary, SRT paste. Merges Manual run and Ready video into stage panels.
2. **Prepare + bulk clean:** locked clean preset on the funnel; bulk clean queue (one at a
   time on Railway, to keep memory flat).
3. **Phone:** responsive cards, Queue home, Calendar, PWA, email notifications.
4. **Drive connect + GitHub Actions clean:** already proposed as a cloud session for 2nd Nov.
5. **Sheet lane aligned** to the same stages.

## Decisions (user, 30-10-2026)

1. **Sources:** a funnel can have **several sources**; each instance comes from exactly
   one of them.
2. **Generated lane:** it **stays**. It rolls out after all the keys are set and the
   roadmap is drawn up; it is not part of phases 1–3.
3. **Alerts:** **email only** (no WhatsApp).
4. **Phone approval:** transcripts are approved **one by one**, never in bulk.

## Priority (why the lanes exist)

- Only **videos** get organic traction; image posts get little or none. Image-only lanes are
  low priority.
- The day-to-day need is the **ready-video lane**. Many finished videos only need
  thumbnails, captions, a schedule and posting. NotebookLM videos also need the clean
  step.
- The lanes exist to keep regular posting going at low cost. The alternative is approved
  script → HeyGen/Kling → approve → post daily; that is the generated lane, held for
  later.
- So phase 1 builds the ready-video lane properly first (funnel sources, transcript gate,
  copy/thumbnails, schedule), with the stage model shaped so the sheet and generated lanes
  slot in later.
